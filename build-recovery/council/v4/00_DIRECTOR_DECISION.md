## 7. طريقة العمل (المالك + Claude السحابي + الجلسة المحلية)

اخترتُ خمساً من تقرير 05 و03:

1. **دفعة سحابية واحدة ← تجميع على اللابتوب ← اختبار جهازين ← الدفعة التالية.**
   لا كود سحابي جديد فوق كود غير مجمَّع.
2. **بطاقة جلسة بهدف واحد** (سؤال نعم/لا، ≤ 7 خطوات، الأدلة المطلوبة) تكتبها
   السحابة قبل كل جلسة. **قاعدة التوقف:** عائق واحد أكثر من 45 دقيقة ← اكتبه في
   `STATUS.md` وتوقف.
3. **السجل أولاً:** لا محاولة على الجهاز قبل أن يسجّل الكود ما نسأل عنه.
4. **نفس الـcommit على الجهازين**، واسم الـAPK يحمل الـcommit، وحساب ثابت لكل جهاز
   مكتوب في ملف (`DEVICES.md`، بلا كلمات مرور).
5. **ملخص 5 أسطر** في `STATUS.md` نهاية كل جلسة. السحابة تبدأ منه. مشروع واحد
   فقط في كل مساء لابتوب.

## 8. بطاقة أول جلسة لابتوب (انسخها للجلسة المحلية)

```
1. اقرأ CLAUDE.md ثم build-recovery/STATUS.md ثم council/v4/00_DIRECTOR_DECISION.md §3.
2. اعرض git status و git log -5 والفرع الحالي. لا تغيّر شيئاً بعد.
3. اسحب بـ git pull فقط (merge). ممنوع rebase أو reset أو force أو حذف أي ملف.
4. إن ظهر تعارض: توقف واعرضه عليّ. لا تحلّه وحدك.
5. اعرض commits اللابتوب غير المرفوعة و git diff لها، وتأكد أن لا أسرار فيها.
6. لا تدفع (push) إلا بعد أن أرى الـdiff وأكتب «موافق».
7. أغلق Unity، ثم جمّع وشغّل EditMode و PlayMode بـbatchmode، وسجّل الأعداد مع الـcommit.
8. لا تقرأ ولا تطبع أي ملف أسرار (.env، google-services، مفاتيح، keystore).
9. هدف الجلسة واحد: البند 2 في §3 VERIFIED. عائق أكثر من 45 دقيقة ← اكتبه في STATUS وتوقف.
10. في النهاية: ملخص 5 أسطر في STATUS.md، اعرضه عليّ، ثم commit و push بعد موافقتي.
```
